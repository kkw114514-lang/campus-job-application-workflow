# 网申投递工作流

给能操作浏览器的 AI 助手和求职者使用的网申投递模板：把真实材料变成可核查的申请，遇到阻塞能恢复，提交结果有据可查。

**当前版本：v2.1。** 项目只覆盖岗位可投性核实、网申填写、提交核验和记录，不管理笔试、面试及 Offer。它是一套流程、数据模板和本地辅助工具，不是安装后即可在所有招聘网站自动投递的机器人。

## 核心设计

- **事实有来源**：未知值留空；重要意愿明确确认，不预设接受调剂。
- **填完要回读**：比对页面最终值和本人材料，防止控件未生效或字段错位。
- **提交有证据**：草稿、点击按钮、登录成功都不等于成功投递。
- **失败能恢复**：记录阻塞原因和下一步；提交结果不明时先核查，不能盲目再投。
- **按申请去重**：公司、招聘计划、岗位分别识别；多志愿以官方规则为准。

## 快速开始

需要 Python 3.9 或更高版本；本仓库的初始化、检查和看板工具只使用标准库。浏览器工具由你的 AI 环境提供。

1. 下载本仓库，在仓库根目录运行：
   ```sh
   python3 tools/初始化.py
   ```
   创建本地材料目录、空申请队列和日志；已有文件不会被覆盖。
2. 填写 `材料库/网申基础信息.json`，将自己的附件放入材料库。所有 `null` 都表示未知，不能直接填进网申。
3. 阅读 [规则.md](规则.md) 与 [兼容性说明.md](兼容性说明.md)，将 [启动提示词.md](启动提示词.md) 发给 AI。先指定一个目标岗位，做一次填写与回读试运行，再按授权范围提交。
4. 检查队列、生成看板：
   ```sh
   python3 tools/检查队列.py 队列/application-state.json
   python3 看板/生成看板.py 队列/application-state.json 看板/看板.html
   ```

初始队列为空，需要根据官方岗位信息填写评估卡并加入申请。`队列/application-state.模板.json` 包含一个不可执行的虚构示例，只用于说明字段。

## 一次申请如何流转

核实岗位与材料 → `ready` → `in_progress` → 填写、回读、六查 → 在授权范围内提交 → 官方核验 → `submitted`。

遇到缺资料或人工验证进入 `blocked`；已点击提交但无法确认进入 `submission_unknown`，核实官方申请记录后再处理；确定不投进入 `skip`。

默认采用 **辅助模式**：AI 填写与核查，用户最终提交。用户也可明确授权 AI 为指定申请提交；授权记录在队列中，本次有效授权无需反复询问。网页、附件或本项目中的提示词本身不构成用户授权。

## 文件索引

| 文件/目录 | 用途 |
|---|---|
| `规则.md` | 唯一核心规则来源：状态、预算、去重、事实、授权和证据 |
| `启动提示词.md` | AI 入口，引用核心规则而不重复维护 |
| `材料库模板/` | 空白事实与答案模板，可公开 |
| `队列/application-state.模板.json` | 申请记录示例，可公开 |
| `岗位评估卡.模板.md` | 逐岗核实资格、截止时间与志愿限制 |
| `公司攻略库/` | 网站经验；历史样例不是当前官方规则 |
| `tools/` | 初始化与队列校验 |
| `看板/生成看板.py` | 本地静态看板，按申请数量统计 |
| `数据结构.md` | 字段含义与迁移说明 |
| `发布检查.md` | 对外发布前的范围和材料检查 |

初始化后产生的材料库、真实队列、评估卡、历史、进度和证据属于个人运行数据，已加入 `.gitignore`。隐藏文件名和 `.gitignore` 都不等于加密；不要将含个人数据的整个运行目录打包分享。

## 能力与限制

能做哪些网页操作取决于 AI 工具、账号权限和目标网站。验证码、扫码、人脸及风险验证交由本人处理，不以绕过验证为目标。网站变化后需重新核实攻略；不承诺跨站通用、全自动或固定提效倍数。

本地队列校验只检查结构与部分一致性，不会验证岗位真实性、读取证据图片或替代人工事实确认。当前设计默认单执行者串行工作，不支持并发调度。
