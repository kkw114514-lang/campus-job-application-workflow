# 跨公司通用坑与对策（实战沉淀）

> 以下每一条都来自真实投递（2026 秋招，20+ 公司）。遇到同款问题直接查这里，别重踩。

## 1. 验证码

- **图形验证码被服务端消耗**：有的银行（如兴业类）每次发码/登录尝试都消耗当前验证码且不自动刷新。对策：点击图片手动刷新 → 重新读码 → 尽快单次登录。读码需放大 8 倍 + OCR 双确认。
- **短信码 5 分钟过期、失败即作废**：必须"发码 → 等短信 → 填双码 → 单次点登录"在 1 分钟内一气呵成。一体化脚本比分步脚本可靠。
- **滑块/拼图（易盾等）**：headless Chrome 几乎必败（即使鼠标轨迹正确，风控仍拒绝）。连续失败 ≥3 次停止，转用户 headed 浏览器人工登录后 AI 接手。不要死磕。
- **hCaptcha 循环**：Lever 等 ATS 在 headless 下可能无限出题（答对也不放行）。转用户在自己浏览器 1 分钟手动投。
- **Cloudflare 拦截提交 POST**：换 UA、换网络时段各试一次仍 403 就转人工在自己浏览器操作（AI 可填好表，用户点 Submit）。

## 2. 表单控件

- **日期控件（dateSlt 类）**：必须模拟真实鼠标按 年→月→日 顺序点选，直接填值不触发校验。
- **下拉选择**：先 dump 全部选项再选，文本必须完全匹配（含全半角）。
- **富文本编辑器**：有的网站"保存失败"会**清空整个编辑器**。对策：填报脚本必须全量重填所有字段，不能只补差量；保存后必须截图验证再进入下一节。
- **承诺/声明 checkbox**：每次进入页面都要重新勾选，别假设上次状态保留。
- **单选通道型控件**（如"身份信息"）：选新值会互斥清空旧值，注意填报顺序。

## 3. 会话

- 银行类校招站会话常 ~30 分钟过期，且**每个脚本必须自带登录**（图形码 OCR + 短信码读取模板），不能依赖上一个脚本的会话。
- 登录成功 ≠ 投递成功，但会话过期 = 所有页面状态作废。恢复点里必须写"会话有效期至约 XX:XX"。
- 标签页崩溃会让会话与验证码同时失效——发码前先确认页面活着。

## 4. 提交与证据

- 第二志愿/多志愿提交常有**确认弹窗**，要点"确认"才真正进队列。
- 提交成功页截图 + 报名序列号 + 岗位名逐字一致，才算 submitted。
- 官网"我的申请/投递记录"页是最强证据，能截就截。

## 5. 渠道纪律

- 同一公司只走一个渠道（不少公司官方明确禁止多渠道重复投递）。
- LinkedIn Easy Apply 需要账号；无账号时优先找官网表单，其次官方邮箱（从官方招聘简章找命名格式），外发邮件需用户授权 SMTP。
