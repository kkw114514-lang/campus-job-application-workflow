# 环境搭建说明（macOS + Playwright）

## 1. 浏览器

- 推荐 Playwright 的 `chromium.launchPersistentContext` 或 `chromium.connectOverCDP`，指定独立 profile 目录（如 `~/Library/Application Support/JobApplicationAgent/browser-profile`）。
- 一个公司/一组任务用一个 profile；常驻调试实例与正式投递实例分开，避免互相踢登录。
- headless 省事但过不了滑块/拼图风控；这类公司直接计划 headed 人工登录 + AI 接手。

## 2. Node 依赖

在项目目录：`npm i playwright`（只用 chromium 可 `npx playwright install chromium`）。脚本模板模式：

```js
const { chromium } = require('playwright');
(async () => {
  const ctx = await chromium.launchPersistentContext(PROFILE_DIR, { headless: true });
  const page = await ctx.newPage();
  await page.goto(URL);
  // dump 字段 / 填表 / 截图
  await page.screenshot({ path: '证据/xxx.png' });
  await ctx.close();
})();
```

每个脚本只做一件事并截图留证；脚本名带公司前缀 + 序号（ccb_7.cjs = 建行第 7 个脚本）。

## 3. 图形验证码 OCR（macOS）

`tools/ocr.swift` 模式：Vision 框架 `VNRecognizeTextRequest` 读屏或读截图。一次失败即截屏存本地改读图，不连续错试。

## 4. 短信验证码（macOS，需用户授权）

`~/Library/Messages/chat.db`（sqlite3）：`text` 列常为空，正文在 `attributedBody`（BLOB）。按 公司签名关键词 + 本次请求时间窗 窄查最新消息提取验证码。iMessage MCP 工具亦可。原则：最小授权、按签名窄查、只取验证码不读其他短信。

## 5. 定时轮询（可选）

用 Kimi 定时任务（cron）每 3 小时跑一次启动提示词，自动处理 ready 队列。注意：手动执行与定时任务不要同时打同一家公司；暂停某家公司时务必把状态改为 blocked（曾发生"口头暂停但状态留 ready 导致定时任务继续执行"的事故）。

## 6. 证据目录

`证据/公司_岗位_日期.png`，命名即检索。提交成功截图 + 官方序列号/文案摘录，双保险。
